# Grok and Cline relay test design

After C4 acceptance, define immutable contract cases and shared assertions in `tests/contracts/`. Run `tests/unit/relay.contract.test.mjs` with independent in-memory process, clock and file providers. Run `tests/integration/relay.contract.test.mjs` with the same cases and assertions through the MCP entry point using controlled native stubs and the native checks. The Windows prompt helper's platform-neutral Pester mocks belong in `tests/unit/Protect-GrokPrompt.Tests.ps1` with the `Unit` tag. `VerifyMocks` and `TestUnitRelay` run those mocks on both hosts. The real temporary filesystem and ACL checks belong in `tests/integration/Protect-GrokPrompt.Tests.ps1` with the `Integration` and `Windows` tags. `NativeQualification` and `TestIntegrationRelay` select those checks on Windows.

### R03 Grok

- Assert the exact argument array for each platform and mode in the Grok contract, including `--verbatim` in both modes. Reject changed or omitted flags and prompt bytes in argv. Verify protection before writing and cleanup on success and caught failure. Reject writes or Grok launches after failed protection or missing Windows `pwsh.exe`. Check that a cleanup failure includes the owned residue path.
- With exit code zero, return nonempty string `text` from an `end_turn` or `refusal` result. Reject an error object even at exit zero, a nonzero exit with answer text, invalid JSON, missing or unknown stop reasons, and missing, nonstring or empty `text`. Exercise `max_tokens`, `max_turn_requests` and `cancelled` with answer text present. For each failure, assert an MCP tool error in the documented category, no partial answer, and the lifecycle checks in R05.

### R04 Cline

- In both modes assert exact argv `--acp --auto-approve false --cwd STARTUP_CWD`, an `initialize` request with `protocolVersion: 1` and no client filesystem or terminal capability, and exactly one `session/new` request with `cwd` equal to the server startup directory and `mcpServers: []`. Reject a missing or true `--auto-approve`, changed launch or session cwd, a different protocol version, an advertised filesystem or terminal capability, a missing or nonempty `mcpServers`, and a second session.
- Assert exactly one `session/prompt` containing a single text block equal to the accepted prompt, including a slash-prefixed prompt and one with surrounding whitespace. Reject altered, trimmed, prefixed or split payloads. Check answer chunks in arrival order across tool calls and ignore other-session and non-answer updates.
- Assert the native string, array and object read/search forms, nullable and stringified editor fields, and both `apply_patch` payload shapes with kind `other` in write mode. Echo the exact offered `allow_once` ID when a request is allowed. In both modes deny Bash, run_commands, WebFetch, fetch_web_content, WebSearch, web_search, Agent, spawn_agent, an MCP tool name, Delete, Move, an unknown tool name, null or missing rawInput, an allowed title with the wrong kind, malformed permission envelopes and mismatched sessions. In read mode also deny Edit, Write, editor and apply_patch. Echo the offered `reject_once` ID and cancel when the required `reject_once` or `allow_once` option is absent. Reject invented option IDs and assert JSON-RPC `-32601` for unsupported client requests.
- Accept only a `session/prompt` response with the active request ID, `stopReason: end_turn` and nonempty attributable answer text. An `end_turn` with textual refusal still returns that text. Assert that a mismatched response ID cannot complete the call successfully. For either mode, a matching JSON-RPC error to `initialize`, `session/new` (including `authRequired`) or `session/prompt` returns a native-failure MCP tool error. Exercise prompt errors after answer chunks. A matching prompt result with a missing or unknown stop reason or with `end_turn` and an empty answer returns a protocol error. Exercise `max_tokens`, `max_turn_requests`, `refusal` and `cancelled` as incomplete stops with answer chunks present. In each failure case assert one MCP reply with `isError`, no partial answer, and child closure and slot release once without waiting for the deadline.

`nuke VerifyMocks` runs the independent proof, including correct mock responses and expected rejection of each negative mutation, before production code. `nuke NativeQualification` checks Q01/Q02 native primitives through a test-side process provider that uses the same argument, permission, prompt and sentinel assertions. Prove that provider with the mocks before using native CLIs. Use PowerShell to orchestrate the checks. The Windows prompt transport first proves ACL creation before writing bytes in the integration check. Do not rely on an unbuilt product helper for pre-adapter validation.

Implement the adapters after the green mock and native gates. Bind the same assertions to the current MCP server. `nuke TestUnitRelay` and `nuke TestIntegrationRelay` run the separate suites. Give each OS-dependent integration case its matching `Windows` or `Linux` tag, including the R02 executable-discovery cases. `nuke Validate` runs all common cases and the matching OS cases, including native cases through the production entry point. Select the case set before execution. Record each selected case ID and the total for that host, retain the original reports and TRX, and require zero failures, zero skips, and execution of every selected case. Obtain the independent release verdict. Architecture inspection has its own receipts and precedes executable fixtures.
