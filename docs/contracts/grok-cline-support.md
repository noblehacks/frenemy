# Grok and Cline relay contract

## MCP surface

Extend `ask-claude-mcp.mjs` in place. Each new tool has one required string property, `prompt`, with description “A complete, self-contained instruction for the selected agent.” Missing, nonstring, empty or whitespace-only prompts return an MCP tool error with text `<tool>: invalid prompt` and do not spawn a child. Preserve accepted prompt text verbatim. The tool name selects the executable and read or explicit write mode. A call waits for one MCP text answer or tool error. Keep the existing handling of unknown tools, JSON-RPC framing, and the Claude tools' existing schemas and descriptions.

- `ask_grok` - Ask Grok Build a question about the current workspace. File edits are disabled.
- `ask_grok_write` - Ask Grok Build to make changes. This call may edit files.
- `ask_cline` - Ask Cline CLI a question about the current workspace. File edits are disabled.
- `ask_cline_write` - Ask Cline CLI to make changes. This call may edit files.

Run in the fixed server startup directory with the CLI's native authentication. Startup cwd selects where the CLI starts. The native CLI owns file operations and its path permissions. Frenemy selects or approves native tool categories by mode. Spawn with an argument array and `shell: false`. Support optional absolute `--grok-executable` and `--cline-executable` paths to existing regular files. On Windows require the `.exe` extension, case-insensitive. On Linux accept a file executable by the current process, including an executable with a shebang. With no override, use `grok.exe` and `cline.exe` from absolute PATH entries on Windows and `grok` and `cline` from PATH on Linux. Missing CLI, invalid override, or a file the OS cannot launch returns a tool error for the affected CLI. Neither added CLI is a prerequisite for the existing Claude tools.

After prompt validation, a Grok or Cline call on any platform other than Windows or Linux returns the MCP tool error `<tool>: unsupported platform` before executable discovery, process launch, or prompt-file preparation. Existing Claude calls keep their current platform behavior.

New calls share the existing four-call counter and ten-minute deadline, including any prompt preparation. Cap the final answer and each cumulative inbound child stream (stdout and stderr) independently at 2,097,152 UTF-16 code units after incremental UTF-8 decoding. For Cline, every received ACP message counts toward stdout, even after parsing and releasing the frame. Outbound requests do not count. A total equal to the limit is valid. Release the slot once on every terminal path. On timeout or overflow terminate the owned direct child and ignore later events. Keep the existing result sanitization and stdin framing guard. Errors identify the tool and failure category and use the existing MCP tool error shape.

## Grok Build

Use the single-turn `--no-auto-update --verbatim --prompt-file FILE --output-format json` interface. Read adds `--permission-mode dontAsk --tools read_file,grep,list_dir --deny Edit --deny Write`. Write uses `--permission-mode acceptEdits --tools read_file,grep,list_dir,write,search_replace`. Both pass `--deny Bash --deny MCPTool --deny WebFetch --deny WebSearch --disable-web-search`. Linux read also passes `--sandbox read-only`; Windows uses the native tool controls. Write follows the native edit bundle, which may expose Delete.

Create one protected temp file for the prompt because the native interface accepts a filename. Write UTF-8 without BOM. Keep prompt bytes out of argv. Create an exclusive directory and file, restrict Linux permissions to 0700/0600 and use the Windows prompt ACL helper to grant only the running user and SYSTEM before writing. On protection failure return an error before writing or spawning Grok. Remove the owned temporary entries after success or a caught failure. Report cleanup failure with the owned residue path. On Windows resolve the native pwsh.exe using absolute PATH entries and invoke the fixed repository helper with the owned directory as an argument. A missing PowerShell host is a Grok invocation error. The helper is invocation plumbing for this binding.

Parse one native JSON result after exit code zero. Accept `stopReason` of `end_turn` or `refusal` with a nonempty string `text`. Return that text, including a refusal. A native error object or nonzero exit is a native failure. Invalid JSON, an unknown or missing stop reason, or missing or empty text is invalid output. `max_tokens`, `max_turn_requests`, and `cancelled` are incomplete output and return an MCP tool error without partial text. Verify write effects separately during validation. [Headless interface](https://docs.x.ai/build/cli/headless-scripting), [permission rules](https://docs.x.ai/build/features/permissions), and [Grok sandbox profiles](https://docs.x.ai/build/features/sandbox).

## Cline CLI

Launch the native executable with `--acp --auto-approve false --cwd STARTUP_CWD`. Initialize ACP protocol 1 with no client filesystem or terminal capability. Create one session in that directory with an empty additional MCP-server list. Submit the accepted prompt unchanged in exactly one ACP text content block. Concatenate in arrival order the text `agent_message_chunk` updates from that session during the active prompt, including text before or between tool calls. Ignore thought, tool and other-session updates. Require the matching `session/prompt` response with `stopReason: end_turn` and a nonempty answer, then close the child. `max_tokens`, `max_turn_requests`, `refusal`, and `cancelled` are incomplete output. An unknown or missing stop reason or empty answer is a protocol error. Return an MCP tool error without partial text on these failures. A textual refusal delivered in a successful `end_turn` remains answer text. [Cline CLI flag source](https://github.com/cline/cline/blob/d3ecc4890e8f9bcb77182b96c77fa90575e8e145/apps/cli/src/commands/program.ts) and [ACP stop mapping](https://github.com/cline/cline/blob/d3ecc4890e8f9bcb77182b96c77fa90575e8e145/apps/cli/src/acp/acpAgent.ts).

Classify permission requests by the exact title token, expected kind, top-level `rawInput` shape and active session ID. A title is the tool name or that name followed by `: ` and its details. Cline validates native argument semantics.

- Read and write permit `Read` (read) and `Glob`/`Grep` (search) with object inputs. For `read_files` (read) and `search_codebase` (search), accept native string, array and object input forms. Reject null or missing input.
- Write also permits `Edit`/`Write`/`editor` of kind edit. For `editor`, require a nonempty string `path` and string `new_text`. Accept omitted or null `old_text` and `insert_line`, string `old_text`, and a positive one-based `insert_line` supplied as a safe integer or its decimal digit string. [Pinned Cline input schema](https://github.com/cline/cline/blob/d3ecc4890e8f9bcb77182b96c77fa90575e8e145/sdk/packages/core/src/extensions/tools/schemas.ts).
- Write also permits `apply_patch` with the pinned kind `other` and a nonempty patch string supplied directly or as an object with string `input`. Patch effects follow Cline's native implementation. The tool is denied in read mode.
- Deny shell, web, delegation and MCP tool calls, standalone Delete/Move, unknown names, malformed permission envelopes and invalid input shapes, wrong kinds and mismatched sessions. For allowed operations select an offered `allow_once`; otherwise select offered `reject_once`. If the required option is absent, cancel. Echo the offered option ID. Reply method-not-found to unsupported client requests.

Return only final attributable answer text. A matching JSON-RPC error from `initialize`, `session/new` (including `authRequired`) or `session/prompt` is a native failure. Errors return the existing MCP tool error shape without partial answer text. On a terminal error, close the child and release the slot once. Timeout and overflow handling follow the shared contract. Test actual file effects independently of ACP answer text. [Native permission source](https://github.com/cline/cline/blob/d3ecc4890e8f9bcb77182b96c77fa90575e8e145/apps/cli/src/acp/permissions.ts).

## Scope of native controls

The relay controls the native invocation and the operations it requests or approves through that interface. Native behaviors outside that interface are outside this contract. The [validation design](native-binding-qualification.md) verifies that the selected interfaces enforce the promised read and explicit write operations on suitable test hosts. An unavailable or incompatible CLI produces a tool error. Record tested versions as evidence.
